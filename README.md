# 村中有事 · Village Tales

> 一个村长处理村庄纠纷的原创叙事推理网页游戏。四桩连环案件，原告被告双线对话，第三方插嘴机制，最终推演回溯所有决断留下的痕迹。

***

## 🎮 在线体验

1. 🌐 **在线体验**：直接访问 [https://bjt-2002.github.io/village-tales/](https://bjt-2002.github.io/village-tales/) （GitHub Pages 托管，人人可访问）
2. 📂 本地运行：仓库 clone 后双击 `index.html` 即可运行，无需安装任何依赖、无需启动本地服务（推荐，响应更流畅）。
3. 首次进入需要在封面的 **API Key** 按钮填入自己的 OpenAI 兼容 Key（以及可选的自定义地址/模型）。Key 保存在玩家本地 `localStorage`，**不会上传到任何服务器，仓库源码内也未内置任何 Key**。

## ✨ 项目特色

| 特色                    | 说明                                                          |
| --------------------- | ----------------------------------------------------------- |
| 🎭 **4 桩原创连环案件**      | 地精 vs 树精、精灵 vs 男巫、魔法师 vs 兽人少年、女巫 / 混血精灵 / 长老 三方对峙           |
| 🗣️ **统一对话流 + 多角色插嘴** | 原告被告同框立绘，自由切换提问对象；核心利益/名誉/秘密被触碰时，另一方会按约 40% 概率插嘴辩护          |
| 🧠 **大模型 Prompt 工程**  | 严格 JSON Schema 输出（`main` 主回答 + `interrupts` 插嘴数组），询问无次数上限   |
| 📜 **羊皮纸线索系统**        | 每案 3 条线索，点击任意位置关闭                                           |
| 🧾 **决断 + 本案演变推演**    | 提交决断后，模型推演案件接下来如何发展；前 3 案"继续"、第 4 案"村庄后续"进入最终推演             |
| 🌅 **主场景全屏最终推演**      | 四案结束后一次性总推演，【发展概览】+【未来终章】双层结构，450-550 字，段落淡入动画；完整性校验 + 自动重试 |
| 💾 **6 坑位存档系统**       | 固定 6 坑位、支持覆盖写入与单独删除、存档永不丢失上限、回合制不设上限说明                      |
| 🎵 **循环 BGM + 静音按钮**  | 右上角小喇叭切换，刷新后默认恢复播放（不保留静音态）                                  |
| 🔒 **隐私安全**           | API Key 存玩家本地浏览器，不进代码，不发第三方                                 |

## 🛠️ 技术栈

- **原生 HTML5 / CSS3 / ES6+ 单文件应用** — 不借助框架、构建工具、脚手架，独立完成完整交互闭环，体现前端基础功
- **CSS3 Animation** — 简介页淡入、游戏介绍浮起、决断结果滑出、最终推演段落淡入
- **Web Audio /** **`<audio>`** — BGM 循环播放 + 捕获阶段首次点击自动解锁（解决浏览器自动播放策略）
- **`localStorage`** — API Key 存储 + 6 坑位存档系统
- **LLM API（OpenAI 兼容协议）** — 可自定义 API 地址 + 模型名
  - 角色询问：返回 `{main: {speaker, content}, interrupts: [{speaker, content}]}` 结构
  - 本案推演：返回案件后续演变叙述
  - 最终推演：内置字数 / 小标题 / 分段长度三重校验 + 自动重试
- **Prompt Engineering 设计** — 插嘴触发覆盖 13 类条件（核心利益、家族名誉、亲人爱人、秘密线索、族群矛盾、嫁祸指控等），模拟真实庭审

## 🚀 运行方式

### 方式 A：本地直接打开（最快）

```bash
# 任选其一
1. 双击 index.html
2. 任意静态服务器：
   Python:  python -m http.server 8000
   Node:    npx serve .
```

### 方式 B：托管到 GitHub Pages

推送到 GitHub 后，在仓库 **Settings → Pages** 中：

- Source: `Deploy from a branch`
- Branch: `main` / `/(root)`

等待约 2 分钟即可获得在线链接。

直接把项目目录拖到对应平台的仪表盘，或把仓库关联平台，零配置即可部署。

```
                  │           index.html                │
                  │                                     │
   点击封面按钮 → │ state 对象管理进度 / 对话 / 存档     │ → 渲染对应 screen

   提交决断     → │ 本案推演 callLLM → narrative        │
                  │   └─ 案件 1-3: "继续" 下一案件      │
                  │   └─ 案件 4:   "村庄后续" → finalEnding

                  │   └─ 四案全量 Prompt                │

```

### 关键设计决策（作品集面试点）

1. **对话流为什么从分栏改成统一流？** 降低用户切换提问对象的心智负担，原告被告插嘴自然出现在同一条对话链里，颜色区分角色。
2. **插嘴机制怎么做的？** 不是固定概率随机，而是 Prompt 明确 13 类触发条件 + 40% 基准概率，让模型判断是否返回 `interrupts` 数组；既保证真实感又避免过度刻意。
3. **终章为什么不逐案出？** 叙事收束感更强，四案决断都沉淀到最后一次「村庄的未来」回放，每条线索有回响、每次决断留痕迹。
4. **存档从"动态追加"改成 6 固定坑位？** 减少玩家"新建还是覆盖"的决策焦虑；每个坑位独立删除，保留老派 RPG 味道。
5. **API Key 存 localStorage？** 零后端项目的必然选择——既避免在仓库里硬编码 Key 造成泄露，又无需自建代理服务器；公开部署 Pages 也安全。

### 踩过的坑 & 修复

| 坑              | 根因                                     | 修复                                                                                                       |
| -------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 简介页首次点击不进下一页   | BGM 播放 `click` 事件冒泡与简介点击冲突，BGM 先把事件消耗了 | `addEventListener('click', ..., true)` 改为**捕获阶段**，简介页优先处理                                                |
| 终章内容不完整 / 只有一半 | 模型 tokens 被截断或两段长度失衡                   | **完整性三重校验**：总字数 420-620 + 两段各 ≥150 字 + 小标题都存在；失败自动加重试 Prompt 再跑一次                                        |
| 逐字动画中文字距怪异     | 每个字包 `inline-block` span，浏览器按字格对齐导致拉伸  | 改为**整段淡入**（`opacity + translateY + blur`）；用 `text-align: justify; text-justify: inter-ideograph` 做中文两端对齐 |
| 老存档含被删字段报错     | 取消"5 轮询问上限"后 `roundsLeft` 字段残留旧存档      | 存档序列化 / 反序列化全部移除该字段，读档时忽略未知字段                                                                            |
| 终章按钮太早出现       | 文字动画还在播放，按钮直接显示                        | `renderEndingAnimated` 返回精确总时长（最后一段 delay + fade + 缓冲），`setTimeout` 等完再显示按钮                              |
